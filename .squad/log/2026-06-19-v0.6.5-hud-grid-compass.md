## What Shipped

### Feature 1: Compass/Heading Metric
- **MetricKind.heading** — 9th selectable HUD slot metric, valid for all workout types
- Sourced from **CLLocationManager** (magnetometer, works indoors, GPS-free)
- Render as **8-point cardinal + degrees** (e.g., `"NE 045°"`) on glasses
- `RunMetricFormatting.formatHeading(degrees:)` pure Core; no CoreLocation imports
- Watch only starts magnetometer when `headingAvailable()` AND layout slot uses `.heading` (efficiency gate)
- True heading preferred, magnetic fallback; calibration overlay suppressed; throttled at source (integer-degree bucket changes)
- **Tests:** formatHeading boundary table (0→"N 000°", 45→"NE 045°", ..., 359→"N 359°"), validity all 6 types, unitLabel empty, metricStrings snapshot test

### Feature 2: Variable HUD Grid (Configurable Lines + Adaptive Fonts)
- **HUDGridConfig { lines: [Int] }** — Codable model (2–4 lines, each 1 or 2 items, e.g. `[2,1,1]` for default)
- **Backward-compatible:** `HUDLayout.grid: HUDGridConfig?` optional; `nil` → legacy `[2,1,1]` byte-identical to v0.6.4
- **No WCMessage schema bump** — field rides inside existing `HUDLayout` Codable (lenient decode tolerates additive field on pre-0.6.5 decoders)
- **Geometry in code:** `HUDGridDefinition.make(for:)` emits flat Slot array per config; all pixel coords + fonts validated in unit tests, never user-editable (rc11→rc16 regression firewall)
- **Adaptive fonts:** 2-line=font 4/3, 3-line=font 3/2, 4-line=font 2/2 (fewer lines/items → taller font)
- Vertical skeletons derived from bench-validated `standard4` + Weiss's coordinate/font tables; **non-`[2,1,1]` coords marked `// TODO(bench)`** for Engo 2 calibration

### Feature 3: Phone Editor — Icons + Variable Grid Controls
- **SF Symbols parity:** full-strength icons for glasses-backed metrics (duration/heartRate/distance/pace), muted for text-only (speed/cadence/energy/elevation/heading)
- **Grid editor:** line-count (2/3/4) + per-line items (1/2) controls; slot cells adapt; selections preserved (truncate/extend)
- **Heading entry:** displays as "Compass"/"Dir" with `location.north.line` SF Symbol
- Preview reflects chosen grid + adaptive fonts

### 4-line (Medium Risk — EXTRAP crowding)

- Font 2 proven at 2-item (from `standard4` slots); question is 26px inter-line gaps + 4 rows don't descender-collide
- Drop-offset 0 (no font mixing)

### Validation Checklist (per new lineCount × per-line items combo)
1. **Blank screen / off-panel clip** — each line actually appears; no text anchored past `x_fb < 0` or `y_fb` band off-panel
2. **Vertical overlap** — adjacent lines don't collide (descenders clear); check 4-line especially (tightest gaps)
3. **Horizontal clipping** — long values (`"1:23:45"`, `"5.00 km"`, `"045°"`, `"NW"`) don't overflow right edge, worst on 2-item right slots and wide font-4/5 1-item lines

### Bench-Gated Follow-Up

## Context: Why These Features

**v0.6.4 shipped** with fixed 4-slot `standard4` grid + phone editor. Users requested:
1. Heading metric for directional awareness (especially outdoor runs)
2. Variable grid sizes (some want dense 4-line, others want big-font 2-line)
3. Preview icons to match on-glass rendering (phone editor parity)

**Design approach:** constrained-custom via parameterized `txt` rendering (no `layoutSave` / font upload / flash burn). All geometry stays in code (validated in tests) to prevent rc11→rc16 class of coordinate-regression bugs.
