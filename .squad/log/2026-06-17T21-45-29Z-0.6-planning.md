**Open for jkrilov Review:** 29 open questions across all agents (6 from Richards, 8 from Killian, 6 from Amber, 5 from Weiss).

### Feature 2: Custom Glasses Layouts
**Scope:** Phone-side HUD layout editor; watch-side custom layout support via WCMessage sync.

**Agents & Deliverables:**
- **Weiss (AR)** — Feasibility verdict + design: constrained-custom model (fixed-grid, user picks metrics per slot), BLE rendering unchanged, pre-existing bugs documented.
- **Killian (Product)** — Phone UX: layout editor in Settings (v0.6.1), per-type default assignment, preview screen.
- **Richards (Architect)** — Data model: `HUDGridDefinition`, `WorkoutLayoutDefaults`, WCMessage payload design.
- **Laughlin (watchOS)** — Watch-side layout persistence + application at workout start.
- **Amber (QA)** — Validation tests for metric/sport compatibility.

**Key Decisions Locked:**
1. **layoutSave (dynamic layout) inappropriate for v0.6.x** — requires cfgWrite + font/icon uploads (matches icon spike), loses preloaded fonts/icons. Deferred to v1.
2. **Raw `txt` (parameterized frame rendering) is the right foundation** — existing RunningHUDFrame.frames(for:) already does the heavy lifting; constrain via fixed-slot geometry.
3. **HUDGridDefinition (compile-time geometry)** — keeps all coordinate logic in code (validated in unit tests), prevents regression class of bugs.
4. **Two confirmed bugs in dormant curated path** (widgetUpdate phantom command, displayLayout payload) — documented, must be fixed before that path activates (not blocking Feature 2).
5. **Phasing:** v0.6.0 per-type code-defined defaults, v0.6.1 phone editor UI, v1+ freeform+layoutSave.

**Open for jkrilov Review:** 5 open questions from Weiss (constrained model acceptable; grid count; icons; metric gating; CloudKit sync).
