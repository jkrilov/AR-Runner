# Skill: XcodeGen — diagnosing the stale-generated-project failure mode

**When to use:** Someone reports `Cannot find 'TypeName' in scope` (or similar "missing symbol" / "missing target membership" errors) for a Swift file that demonstrably exists on disk in an Xcode project that is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen).

**Why this matters:** "Missing Xcode target membership" is one of the most common Apple-developer footguns in hand-managed `.xcodeproj` files, and the muscle-memory fix (edit the four pbxproj sections — `PBXBuildFile`, `PBXFileReference`, `PBXGroup`, `PBXSourcesBuildPhase`) is correct in that world. Under XcodeGen it is **always wrong**:

- The `.xcodeproj/` is gitignored and regenerated from `project.yml`.
- A target's `sources: [path: SomeDir]` is recursive — every `.swift` under `SomeDir/` is auto-included.
- Any hand-edit you commit either (a) gets overwritten on the next `xcodegen generate`, or worse (b) gets committed as a gitignored file (CI break next regen).

The actual fix is one command. The hard part is recognizing that's what you're looking at before sinking time into a pbxproj patch.

## 30-second triage

Run from the repo root:

```bash
# 1. Is the project file gitignored? If yes, it's generated.
git check-ignore AR-Runner.xcodeproj/project.pbxproj && echo "GENERATED — do not hand-edit"

# 2. Is XcodeGen the generator?
test -f project.yml && echo "XcodeGen project"

# 3. The fix:
xcodegen generate
```

If steps 1+2 are positive, you're done — no pbxproj edits, no PR, no UUIDs. The reporter just needs to regenerate locally.

## When to actually edit pbxproj

Only when:

- `git check-ignore` does **not** match (project bundle is tracked in git), AND
- there is no `project.yml` / `Tuist/` / `xcake` / other generator config in the repo root.

In AR-Runner, this is never the case. `*.xcodeproj/` is gitignored in `.gitignore`.

## What CAN go wrong under XcodeGen (the real review checklist)

If a new file genuinely is invisible to a target after `xcodegen generate`:

- The file lives outside any target's declared `sources` path (e.g., a stray `Shared/` directory not referenced in `project.yml`).
- The file is excluded by an `excludes:` glob.
- The file is in a target whose `sources` uses `optional: true` and the path doesn't exist as expected.
- A new target was added but `project.yml` wasn't updated to declare it.

So the PR-review check for new Swift files in this repo is **not** "is it in pbxproj"; it's **"is it under an existing `sources` path declared in `project.yml`, and not excluded?"**
