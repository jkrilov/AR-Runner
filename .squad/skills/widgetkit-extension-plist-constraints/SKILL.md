# WidgetKit Extension Info.plist Constraints

**Owner:** Laughlin
**Status:** Active
**Created:** 2026-05-15 (PR #17)

## Problem

`xcodebuild build` does NOT validate WidgetKit extension Info.plist constraints. `simctl install` (and SwiftUI Preview host install) DOES. CI can be fully green while local install / Preview is broken.

Failure mode (verbatim from `installd` / `IXUserPresentableErrorDomain`):

> Appex bundle Foo.appex with id com.example.widgets defines either an
> NSExtensionMainStoryboard or NSExtensionPrincipalClass key, which is not
> allowed for the extension point com.apple.widgetkit-extension

## The constraint

For extension point `com.apple.widgetkit-extension`, the `NSExtension` dict in the appex `Info.plist` MUST contain ONLY:

```xml
<key>NSExtension</key>
<dict>
    <key>NSExtensionPointIdentifier</key>
    <string>com.apple.widgetkit-extension</string>
</dict>
```

**Forbidden keys** (will fail install, NOT build):

- `NSExtensionPrincipalClass` — entry point is the Swift `@main WidgetBundle` type, not a plist-declared class
- `NSExtensionMainStoryboard` — WidgetKit is SwiftUI-only; storyboards are nonsensical here
- `NSExtensionAttributes` — no longer used by WidgetKit (legacy Today-extension key)

These keys are leftovers from pre-WidgetKit `NSExtension`-style extensions (Today widgets, share extensions). When scaffolding or converting to WidgetKit, strip them.

## How to fix in this repo (XcodeGen)

`project.yml` defines widget targets with inline `info.properties` (NOT a checked-in Info.plist). The plist is regenerated by `xcodegen generate` into `Config/ARRunnerWidgets{Phone,Watch}-Info.plist`.

Correct shape:

```yaml
ARRunnerWidgetsWatch:
  type: app-extension
  platform: watchOS
  # ...
  info:
    path: Config/ARRunnerWidgetsWatch-Info.plist
    properties:
      CFBundleDisplayName: AR-Runner Widgets
      NSExtension:
        NSExtensionPointIdentifier: com.apple.widgetkit-extension
      # NO NSExtensionPrincipalClass
      # NO NSExtensionMainStoryboard
```

Apply to BOTH `ARRunnerWidgetsPhone` and `ARRunnerWidgetsWatch` — the constraint is identical on iOS and watchOS.

After editing `project.yml`, run `xcodegen generate`.

## Verification checklist

After any `project.yml` change touching an extension target:

1. `xcodegen generate`
2. `xcodebuild ... build` — must succeed (necessary, not sufficient)
3. **Inspect built plist:**
   ```bash
   /usr/libexec/PlistBuddy -c "Print :NSExtension" \
     <DerivedData>/Build/Products/Debug-watchsimulator/<App>.app/PlugIns/<Widgets>.appex/Info.plist
   ```
   Expected output:
   ```
   Dict {
       NSExtensionPointIdentifier = com.apple.widgetkit-extension
   }
   ```
4. **Smoke-install on the simulator:**
   ```bash
   xcrun simctl boot <DEVICE_UDID> 2>/dev/null || true
   xcrun simctl install <DEVICE_UDID> <path-to>.app
   ```
   Exit code 0 = pass. Any `IXUserPresentableErrorDomain` mentioning `com.apple.widgetkit-extension` = the constraint is still violated.

## Why CI doesn't catch this

`xcodebuild build` only runs compile + sign + basic bundle structure validation. Extension-point-specific Info.plist contracts are enforced by `installd` (the on-device installer), which only runs at install time. To catch this in CI, add a `simctl install` step for any scheme that embeds an extension target.
