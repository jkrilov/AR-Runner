## Summary

Forensic analysis of rotation value 4 (`topLR`) after rc11 (rotation=4 at x=20) went blank on hardware. Investigation traced the root cause to off-screen clipping per SDK spec §5.5.6, NOT firmware rejection.

## Key Findings

- **All 8 rotation values (0-7) are documented** in the official ActiveLook SDK enum (`ActiveLookTypes.swift:41-50`). Prior skill note claiming "only 0 and 4" was incorrect.
- **The rc11 blank was a coordinate error**: `topLR` (rotation=4) anchors text at the TOP-RIGHT and extends leftward. At leftMargin=20, the entire ~200px string extended into negative framebuffer x, triggering silent clip per spec §5.5.6.
- **Engo 2 lens flip formula** confirmed: `x_wearer = 303 − x_fb`, `y_wearer = 255 − y_fb`. Combined with 180° rotation of glyphs → cancels to right-side-up text for wearer.
- **rc12 fix validated**: rotation stays 4, coordinates move to (leftMargin=284, timeY=166, distanceY=86, paceY=6) to place text on-screen. All 154 Core tests pass.
