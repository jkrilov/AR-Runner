## Scope

Fixed Linux CI failure in PR #8 (workout controller metrics tests).

## Diagnosis

**Root cause:** Single-consumer AsyncStream race condition.  
Both `WorkoutController.forwardingTask` and the test's `bridgeMetrics` subscriber were iterating over the same `substrate.metricEvents` stream simultaneously. On Linux (strict task scheduling) this exposed a consumption race; on macOS (Darwin scheduler) it remained masked.

## Fix

**Changed:** Bridged from `controller.metrics` (controller's re-published stream) instead of directly consuming `substrate.metricEvents`.  
**Effect:** Controller now owns the single consumer on the substrate stream; tests consume the controller's public re-publication.
