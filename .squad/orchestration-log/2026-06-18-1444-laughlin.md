## Summary

Laughlin shipped a robust fix for long-run uploads stuck in `.uploading` state. Root cause: `StravaUploadQueue.uploadOne` persisted the entry as `.uploading` before awaiting a foreground `URLSession.shared.upload`. iOS suspension mid-upload (large TCX over cellular) orphaned the entry; `pickNext()` only selected `.pending`, so reclamation never happened.

**Fix — three parts:**
1. **Reclaim orphans** — `StravaUploadQueue.reclaimOrphans` rewrites persisted `.uploading`→`.pending` at init (idempotency via `external_id` = `HKWorkout.uuid`).
2. **Background URLSession** — New `BackgroundStravaUploadTransport` uses background session config, file-based multipart, `CheckedContinuation` delegate bridge, `PhoneAppDelegate` background-launch hook.
3. **Confirm processing** — New `.processing` state polls `checkUploadStatus` (was dead code) with bounded backoff `[2,5,10,20,30]s` until `activity_id`/`error`/budget exhausted.

**State-machine invariant (enforced):** `pickNext()` selects both `.pending` and `.processing`; `.uploading` reclaimed at init. No persisted state unreachable.
